每帧系统流转示意图

按代码任务图顺序展示。可以把它当成“这个仿真器一帧在做什么”的讲稿。

1) schedule_pending_flows
扫描 pendingFlows，把 start_time ≤ now 的流注入首跳 Arrival 事件。
输出：新事件进入 delayedEvents。
2) deliver_events
取 delayedEvents 中 t ≤ now 的事件，分发到每个端口 PortInbox。
输出：arrival/bwupd/pfc 三类 inbox 已就位。
3) ingress_chain（端口并行）
pfcPropagateOnePort → flowArrivalOnePort → flushTagCreate
bwUpdateOnePort → flushTagCreate → flushTagCleanup → flushFlowCompletion → flushPortOutbox
输出：端口接收侧状态更新完成，必要的新 tag 创建与旧 tag 清理完成。
4) alloc（端口并行）+ 归并
allocOnePort 计算每个 tag 的 out_bw，产生 drain/finish 提示。
reduceHints / flushDrainHints / flushTagCleanup 汇总全局最早事件。
5) emit_pfc（检测与下发）
pfcDetectOnePort 根据 backlog 与阈值决定 pause/resume，并写入 outbox。
flushPfcTimers + flushPortOutbox 后，再 emitOnePort 给下游发 Arrival/BwUpdate。
6) clear_dirty + snapshot_dirty
清理本帧 dirty 标记，并保留“本帧哪些端口曾脏”的快照供下一阶段。
7) chooseDT
从事件到达、流启动、源流完成、drain、PFC timer 等候选里取最小 dt。
应用 dtMin 与兜底规则（异常时回退到 0.001）。
8) buffer + progress
advanceOnePortBuffer(dt) 推进 backlog/chunk，必要时延迟清理 tag。
flowProgressAndCleanupSystem(dt) 处理完成与计时器，最后 now += dt。
一句话总结：先“收事件”，再“算带宽并发事件”，最后“推进时间并清理”。
