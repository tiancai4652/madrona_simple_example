# 0.init：构造函数与外部参数如何传进 Madrona（业务逻辑版）

这份文档只讲你关心的两件事：
1. 外部传进来的参数，怎么一路到 `Sim::Sim(...)`。
2. `Sim` 构造函数里，业务上到底初始化了什么。

## 1. 参数入口（Python）

外部通常从 Python 的 `GridWorld(...)` 进来：
- 文件：`src/madrona_simple_example/gridworld.py`
- 它收两类输入：
  - 网格输入（walls/rewards/end_cells/start）
  - 网络输入（nodes/links/flows）
- 还有仿真配置：`propagation_interval`、`enable_pfc`、`pfc_egress`、`dt_min`、`qos_mode`、`prior_weights` 等。

然后它调用 C++ 绑定构造器 `SimpleGridworldSimulator(...)`。

## 1.1 传入字段都是什么意思（重点）

下面按你真正传参的层级来解释。

### A) `GridWorld(...)` 的参数（Python层）

- `num_worlds`
  - 含义：并行 world 数量（复制同一份输入跑多份环境）。
- `start_cell` / `end_cells` / `rewards` / `walls`
  - 含义：grid 示例相关输入；对“流仿真主逻辑”影响较小，主要用于兼容示例接口。
- `gpu_sim`
  - 含义：是否走 CUDA 执行模式。
- `gpu_id`
  - 含义：使用哪张 GPU。
- `network_inputs`
  - 含义：核心网络业务输入，包含 nodes/links/flows。
- `propagation_interval`
  - 含义：传播时间量化步长。`0` 表示不量化（直接 `base_time + link_delay`）。
- `enable_pfc`
  - 含义：是否开启 PFC 逻辑（0 关，非0 开）。
- `pfc_egress`
  - 含义：PFC 检测模式。`0`=ingress 检测，`1`=egress 检测。
- `pfc_xoff_threshold`
  - 含义：PFC 触发 PAUSE 的 backlog 阈值。
- `pfc_xon_threshold`
  - 含义：PFC 触发 RESUME 的 backlog 阈值。
- `dt_min`
  - 含义：仿真最小步长下限。
- `qos_mode`
  - 含义：队列调度模式。`0`=NONE，`1`=SP，`2`=WRR。
- `prior_weights`
  - 含义：WRR 每个优先级权重（最多8个优先级）。

### B) `network_inputs` 里的字段（拓扑与流定义）

#### 节点字段（对应 `NodeDef`）
- `node_ids`
  - 含义：节点 ID（主机/交换机统一编号）。
- `node_types`
  - 含义：节点类型。`0`=Host，`1`=Switch。
- `node_port_bws`
  - 含义：节点端口默认带宽（当链路不单独给带宽时使用）。

#### 链路字段（对应 `LinkDef`）
- `link_srcs` / `link_dsts`
  - 含义：链路两端节点 ID（输入是无向语义，内部会扩为双向）。
- `link_delays`
  - 含义：链路传播时延。
- `link_bandwidths`
  - 含义：链路带宽；若为 0，则回退到节点默认端口带宽。

#### 流字段（对应 `FlowDef`）
- `flow_ids`
  - 含义：流唯一 ID。
- `flow_src_nodes` / `flow_dst_nodes`
  - 含义：流源节点、目的节点。
- `flow_sizes`
  - 含义：流总大小（字节）。
- `flow_start_times`
  - 含义：流启动时间（仿真时间）。
- `flow_priorities`
  - 含义：流优先级（通常映射到 0~7）。

### C) C++ 运行配置字段（`Manager::Config` / `Sim::Config`）

- `maxEpisodeLength`
  - 含义：episode 上限步数（此项目中常设为0，不作为主限制）。
- `execMode`
  - 含义：CPU 或 CUDA。
- `numWorlds`
  - 含义：并行 world 数。
- `gpuID`
  - 含义：GPU 编号。
- `default_link_delay`（`Sim::Config` 默认 0.001）
  - 含义：当查不到链路时延时的兜底值。
- `enable_buffer`（当前映射里固定为1）
  - 含义：是否启用 backlog/buffer 机制。
- `enable_pfc` / `pfc_egress`
  - 含义：同上，控制 PFC 功能与检测位置。
- `pfc_xoff_threshold` / `pfc_xon_threshold`
  - 含义：PFC XOFF/XON 阈值。
- `dt_min`
  - 含义：最小时间步长。
- `qos_mode`
  - 含义：调度模式 NONE/SP/WRR。
- `prior_weights[8]`
  - 含义：WRR 权重数组。

### D) `WorldInit` 字段（传给每个 world 的启动上下文）

- `episodeMgr`
  - 含义：episode 管理对象指针。
- `grid`
  - 含义：网格输入指针（示例遗留）。
- `network`
  - 含义：网络输入指针（主业务数据来源）。

## 2. Python -> C++ 绑定层

绑定入口在：`src/bindings.cpp`

这里做了三件事：
1. 把 numpy 数组转成 C++ 的 `NodeDef[] / LinkDef[] / FlowDef[] / Cell[]`。
2. 组装 `Manager::Config`（运行参数）和 `GridState`、`NetworkInit`（业务输入数据）。
3. 调用 `new (self) Manager(config, grid, network)`。

你可以把这层理解成“参数翻译层”：把 Python 世界翻译成 C++ 仿真世界。

## 3. Manager 如何把参数送进 World

核心在：`src/mgr.cpp` 的 `Manager::Impl::init(...)`。

## 3.1 先映射配置

`Manager::Config` 会被转换为 `Sim::Config`，例如：
- `propagation_interval -> Sim::Config::propagation_interval`
- `enable_pfc -> Sim::Config::enable_pfc`
- `pfc_egress -> Sim::Config::pfc_egress`
- `dt_min -> Sim::Config::dt_min`
- `qos_mode -> Sim::Config::qos_mode`
- `prior_weights -> Sim::Config::prior_weights`

也就是：运行策略参数在这里进入仿真核心。

## 3.2 再准备 WorldInit

`WorldInit` 里放的是每个 world 启动时必须拿到的指针：
- `EpisodeManager *`
- `GridState *`
- `NetworkInit *`

`setupWorldInitData(numWorlds, ...)` 会给每个 world 一份 `WorldInit`（内容通常相同，指向同一份输入数据）。

## 3.3 CPU / CUDA 两条路

- CPU：`TaskGraphExecutor<Engine, Sim, Sim::Config, WorldInit>`
- CUDA：`MWCudaExecutor`（把 `Sim::Config` 和 `WorldInit` 指针交给 GPU 执行器）

两条路不同点是内存放在 CPU 还是 GPU，但“业务输入结构”和“构造参数语义”是同一套。

## 4. 真正进入 `Sim::Sim(...)`

构造函数在：`src/sim.cpp`

签名：
- `Sim::Sim(Engine &ctx, const Config &cfg, const WorldInit &init)`

这里 `cfg` 就是上一步传下来的 `Sim::Config`，`init` 就是 `WorldInit`。

构造函数业务顺序（非常关键）：
1. `resetNetworkState()`：清空所有仿真状态（时间、队列、索引、缓存、计时器）。
2. 把 `cfg` 覆盖到运行开关：buffer/pfc/qos/dt/阈值/权重等。
3. 创建 `Agent` 实体（兼容导出列）。
4. 创建 `SimDriverArch` 实体（驱动单例系统）。
5. `loadTopo(ctx)`：读 `init.network->nodes/links`，创建所有 `Port` 实体，建 peer 映射，算路由。
6. `loadFlow(ctx)`：读 `init.network->flows`，填 `flowDefs/pendingFlows`，并按 `start_time` 排序。

到这一步，世界已经“可运行”：
- 拓扑端口都建好
- 待启动流准备好
- 配置开关已生效

## 5. 为什么这样设计（业务价值）

这套传参/构造方式的业务意义：
1. 输入和运行参数分离
- `NetworkInit` 描述“仿真对象是什么”（拓扑和流）。
- `Sim::Config` 描述“仿真怎么跑”（PFC/QoS/步长策略）。

2. 构造函数一次性把世界拉到可执行状态
- 后续 `step()` 不再做重型初始化，只做事件推进和系统计算。

3. CPU/CUDA 语义统一
- 你调参不用分两套业务逻辑。

## 6. 一句话串起来

外部参数路径可以记成：

`GridWorld.__init__`  
-> `bindings.cpp`（numpy 转结构体）  
-> `Manager::Config + GridState + NetworkInit`  
-> `Manager::Impl::init`（转 `Sim::Config` + 组 `WorldInit`）  
-> 执行器创建 world  
-> `Sim::Sim(cfg, init)` 完成业务初始化。
