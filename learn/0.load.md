# 2.load：`loadTopo` 和 `loadFlow` 过程讲解（重点：创建了哪些实体）

你提到的是 `src/sim.cpp` 里的调用点：
- `Sim::Sim(...)` 末尾调用 `loadTopo(ctx)` 和 `loadFlow(ctx)`

这两个函数的实现实际在：`src/sim_init.cpp`。

下面按“先做什么、后做什么、创建了什么实体”来讲。

## 1. 在构造函数中的位置

`Sim::Sim(...)` 里顺序是：
1. `resetNetworkState()`
2. 根据 `cfg` 写入开关参数
3. 创建 `Agent` 实体
4. 创建 `SimDriverArch` 实体
5. `loadTopo(ctx)`
6. `loadFlow(ctx)`

所以 `loadTopo/loadFlow` 发生在 world 已经有基础单例实体之后。

---

## 2. `loadTopo(ctx)` 做了什么

`loadTopo` 的核心目标：
- 把输入拓扑（nodes/links）变成“可计算的端口图”。
- 完成端口实体创建和端口间映射。

### 2.1 读取与校验输入

- 从 `network` 里取：
  - `node_defs = network->nodes`
  - `input_links = network->links`
  - `num_node_defs = network->numNodes`
  - `num_input_links = network->numLinks`
- 做上限校验：
  - 节点数 <= `MAX_TOPO_NODES`
  - 链路数 <= `MAX_TOPO_LINKS`
  - 双向展开后链路数也不能超限

### 2.2 填 `topoNodes`

对每个输入节点，写入：
- `id`
- `type`（Host/Switch）
- `port_bw`
- `num_neighbors = 0`

这一步只是填世界数据数组，不创建 ECS 实体。

### 2.3 把链路扩成双向并写时延矩阵

每条输入链路 `(src, dst, delay, bw)` 会写两条 `topoLinks`：
- `src -> dst`
- `dst -> src`

同时更新 `linkDelays[src_slot][dst_slot]` 和反向。

### 2.4 为每个“节点->邻居方向”创建端口实体（关键）

遍历双向后的 `topoLinks`，对每个源节点的每个新邻居：
1. 分配邻居槽位 `neighbor_idx`
2. 计算端口带宽 `port_bw`
   - 若链路带宽 > 0 用链路带宽
   - 否则用节点默认 `port_bw`
3. 调用 `createPort(ctx, topoLinks[i].src, port_idx, port_bw)`

`createPort` 内部会：
- `ctx.makeEntity<Port>()` 创建一个 `Port` 实体
- 分配 `port_id`（`nextPortID++`）
- 写 `portEntities[port_id]`、`portToNode[port_id]`
- 初始化该端口全部组件：
  - `DirtyPort`
  - `PortState`
  - `PortBuffer`
  - `PortPfcConfig`（若 enablePfc 开启则写阈值）
  - `PortPfcState`
  - `PortCachedHints / PortDrainHint / PortCleanup / PortTraceLast`
  - `PortOutbox / PortTagList / PortInbox / PortCreateList / PortCompletionList`

然后把该端口挂到 `topoNodes[src].neighbors[...]`。

### 2.5 建立端口对端映射与连通标记

再次遍历双向链路，找到两端对应的端口 ID：
- 设置 `peerPort[dst_port_id] = src_port_id`
- 把 `src_port` 的 `PortState.connected = 1`

这一步完成“端口与端口”的互联关系。

### 2.6 计算路由

调用 `computeRoutes()`：
- 计算最短路径/ECMP next hop
- 填 `routeTable / ecmpCount / ecmpNextHops`

这一步也不创建实体，只填全局路由数据。

---

## 3. `loadFlow(ctx)` 做了什么

`loadFlow` 的核心目标：
- 把输入流定义放入仿真状态，准备后续按 start_time 注入。

### 3.1 读取与校验

- 读取 `flow_count = network->numFlows`
- 校验 `flow_count <= MAX_FLOWS`

### 3.2 拷贝到两份数组

- `flowDefs[i] = network->flows[i]`（流的“静态定义池”）
- `pendingFlows[i] = network->flows[i]`（待启动队列）

并设置：
- `numFlowDefs = flow_count`
- `numPendingFlows = flow_count`

### 3.3 按启动时间排序

对 `pendingFlows` 按 `start_time` 升序排序。

这样后续 `schedulePendingFlows()` 可以直接从前往后弹出“到时该启动”的流。

### 3.4 实体创建情况

`loadFlow` **不会创建任何 ECS 实体**。

它只填数组和计数器。

真正的流实体 `FlowTag` 是运行时在事件链里创建的：
- 先由 `schedulePendingFlows()` 生成首个 Arrival 事件
- 再在 ingress 链中通过 `flushTagCreate -> createTagOnPort` 创建 `FlowTag`

---

## 4. 这两个函数到底创建了哪些实体（总结）

## 4.1 `loadTopo` 创建的实体

- 创建：`Port` 实体（数量 = 有向邻接边数）
- 不创建：`FlowTag`、`Agent`、`SimDriverArch`

## 4.2 `loadFlow` 创建的实体

- 创建：无
- 只准备 `flowDefs/pendingFlows`

## 4.3 同一初始化阶段里其它实体（帮助你讲完整）

- `Agent`：在 `Sim::Sim` 里、`loadTopo` 前创建 1 个
- `SimDriverArch`：在 `Sim::Sim` 里、`loadTopo` 前创建 1 个
- `FlowTag`：不是初始化创建，运行时事件驱动创建

---

## 5. 一句话版本（方便你对外讲）

- `loadTopo` = “把拓扑落成端口图，并创建所有 Port 实体”
- `loadFlow` = “把流定义放进待启动队列，不创建 FlowTag 实体”
- 真正的 `FlowTag` 要等仿真跑起来后，Arrival/BwUpdate 到达端口时才创建。
