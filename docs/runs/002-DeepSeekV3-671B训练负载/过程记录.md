### 6.1 recon 结论（Worker/Trace/Config 三件套）
1. Worker≠rank（实现说明 §ServingWorker）：rank=真实 NpuNode，Worker=连续 rank 组成的逻辑执行单元；
   配置校验在 `inference/config.py`：池内 worker 必须首尾相接连续（`_validate_pool`）、P/D 池 rank 不许重叠、
   上限 P/D 各 16 worker、每 worker ≤16 rank、每 batch ≤128 请求（`MAX_INFERENCE_BATCH`）。
   "P/D 等宽"是实现说明第 6 条旧边界，**现代码已放开**（单测 `test_unequal_widths_validate` 过；
   入口 help 写 widths may differ；MLA 分支跳过整除矩阵），本轮仍取等宽 8+8（最简可复现，见 6.3）。
2. request trace 文件格式：`inference/io.py` `load_request_trace` 只收 4 键
   `request_id/arrival_time_ns/prompt_len/output_len`（注意：实现说明正文写 `arrival_ns`，
   **实际 loader 字段是 `arrival_time_ns`**，以代码为准；JSON 顶层 list 或 `{"requests": [...]}`，
   也支持 jsonl/csv；≤1024 条，request_id 唯一，prompt_len>0，其余 ≥0；自动按到达排序）。
3. ServingConfig 模型参数：`--num-layers/--num-kv-heads/--head-dim/--bytes-per-elem` 进 KV 公式；
   `--kv-mode gqa|mla + --kv-latent-dim` 即 `IC_KV_MODE/IC_KV_LATENT_DIM`（config.py 24/25 号槽）；
   `--prefill/decode-reference-tokens` 是无 Profile 线性回退的分母（`实际=模板×tokens/ref`）；
   `--p/d-max-batch/max-tokens` 是组批两把尺；路由已固定 QueueDepth（route policy 参数已废弃）。
4. workload params（OpProfileData）loader：6 键 stage/node_type/batch_size/sequence_tokens/
   duration_ns/comm_size_bytes；stage 只收 1/2（本轮表 stage 全 1，见 6.4）。

### 6.2 request_trace.json（本轮目录新建，已过 loader 校验）
- 内容：4 条，`request_id=0..3`，`arrival_time_ns=0/1ms/2ms/3ms`，`prompt_len=4096`，`output_len=8`。
- 取值理由（一句话一条）：请求数 4=最小能验证 P 组批分批 + D continuous batching 多请求同 active 集，
  又不让 KV/Decode 总量爆炸，用户可调 1~1024；到达等间隔 1ms=可复现、无突发堆积；
  prompt 4096=目录名 seq4096 即训练序列长、对齐模板尺度；output 8=远小于 prompt 的"小值"，
  8 轮 Decode 足以验证 output_done 递增到 Finished，又不至于让 Decode 重放拖死 CPU（用户可调大，
  代价见 6.5）。
- 校验：`load_request_trace` 实测 `rows=4` 通过。

### 6.3 ServingConfig（落盘 serving_config.json，命令行逐项对应）
- Worker：`--prefill-workers 0-7 --decode-workers 8-15`（单 P + 单 D，等宽 8+8、连续不重叠、占满 16 rank；
  理由：与任务示例一致、路由无方差最易复现；恰与 PP 配对 r↔r+8 对应；MLA 下 shards==d_width=8）。
  备选（实测过）：8 个 1 宽 P + 8 个 1 宽 D（同样等宽连续，占满 16 rank，单请求 KV 从 8×287MB 降到
  1×287MB），但实测 KV 后斜率同为 1us/step、优势不如预期，仍用 0-7/8-15 主方案。
- batch/token：`--p-max-batch 16 --p-max-tokens 8192 --d-max-batch 16 --d-max-tokens 32768`
  （沿用 runner 默认；4096 prompt 下 P 每批恰容 2 请求→4 请求分 2 批；D 上下文 4×(4096+8)<32768 不限流）。
- 模型：`--num-layers 61`（DeepSeekV3 层数）；`--kv-mode mla --kv-latent-dim 576`
  （DeepSeekV3 是 MLA 注意力，**代码已支持 MLA 真口径**：kv_transfer.cpp MLA 分支
  `KV= layers×prompt_len×latent_dim×bytes` + config 24/25 槽 + 单测全套 MLA 用例，
  故**不是稠密近似**；576=kv_lora_rank 512+qk_rope 64；`num-kv-heads 128/head-dim 128/bytes 2`
  在 MLA 下仅占位正数、跳过 GQA 整除矩阵，取 V3 注意力头数标记）。
- 回退基准：`--prefill-reference-tokens 4096 --decode-reference-tokens 4096`
  （关键修正：默认 ref=1 会把每轮 Decode 的 duration/comm 放大 prompt 倍≈4096×——模板本就是
  seq4096 实测值，ref 取 4096 使回退中性；Prefill 命中 stage=1 通配 profile、ref 不参与，取同值留档）。

### 6.4 MLA 口径 + Decode 回退说明
- MLA：支持。用 `--kv-mode mla --kv-latent-dim 576`，单请求 KV=`61×4096×576×2≈287.8MB`，
  以完整 latent 从 P0 点对点发往 D worker 每个 rank（shards==d_width=8），与 GQA 按 head 分片不同。
- Decode 回退：本轮 `op_profile.json` 233 行 stage 全 1（训练负载无 P/D 之分的历史假设），
  Decode 查表必失配→走 `op_resolver.cpp` 线性回退（duration/comm ×tokens/ref，ref 已取 4096 中性化）。
  属预期行为、PRD 已定"是否补 stage=2 行待评审、duration 未知不许编"，如实记录、不补数。

### 9.1 一次到位测算（先算值、再改码）
